## App script

| File | Purpose |
|------|---------|
| `gramatica.js` | All SPA logic for `gramatica.html`: level tab rendering, accordion toggle, and hash-based routing over the global `GRAMMAR_DATA` object (117 rules total: A1 21, A2 21, B1 31, B2 17, C1 17, C2 10 — B2/C1 follow the chapter granularity of "Grammatik aktiv B2/C1", Cornelsen) loaded from `grammar-data.js` + `grammar-data-{level}.js`. "🎯 Practicar" quiz (`getPracticeSentences()`): before calling AI, checks `grammar_practice_exercises` (Supabase, keyed by `rule_id`) for a set the current user hasn't seen yet (`user_grammar_practice_seen`, same reuse pattern as `reading_texts`/`user_reading_seen` in `lectura veloz.html`); only when every existing set for that rule was already seen does it call `/api/chat` `action: 'generate-practice'` to generate and persist `PRACTICE_EXERCISE_COUNT` (5) new sentences. Falls back to the rule's built-in `ejemplos` on any auth/network/DB error. `buildQuizQuestions()` turns the 5 sentences into 5 questions y las ordena por dificultad creciente (`QUIZ_RANK`: reconocer → completar → reordenar → producir). Los tipos dependen de si el set trae distractores de par mínimo: con ellos se usan `opcion_multiple` (las 4 opciones son la misma frase variando solo el rasgo evaluado, vía `exDistractores()`), `hueco` y `escribir_hueco` (el hueco se deriva del tramo en que los distractores difieren, `huecoDesdePares()` — el segundo se responde escribiendo) y `ordenar`; sin ellos (filas antiguas, o el fallback a `rule.ejemplos` cuando no hay sesión/red, que ahora se avisa en pantalla) se mantienen los tipos legados `opcion_multiple` / `identificar` / `ordenar` / `articulo`. `quizIsCorrect()` centraliza la comparación: `ordenar` acepta los `ordenes_validos` del set y `escribir_hueco` normaliza mayúsculas/umlauts (`examNormalize`). Al fallar, el feedback muestra el `por_que_mal` del distractor elegido en vez del `tip` genérico, y el rating SRS al cerrar el quiz es proporcional (5/5→4, 4/5→3, 3/5→2, resto 1). Also calls `/api/chat` directly (no caching) for Modo Examen's per-rule exercise generation: el prompt incluye el nivel CEFR de la regla (`ruleLevel()`) y sus temas, exige que la `instruccion` diga explícitamente cuánto se escribe y pide `respuestas_aceptadas[]`; `examCheck()` corrige tolerando mayúsculas, puntuación final, espacios y umlauts escritos ae/oe/ue/ss (avisando de la grafía exacta sin penalizar, y sin admitir alternativas en los ítems de opción múltiple), `verifyExamBatch()` resuelve cada ítem una segunda vez de forma independiente y, si discrepa, añade esa respuesta a las aceptadas en lugar de penalizar al alumno, las preguntas que no llegaron a cargarse quedan fuera de la nota, y el examen "Mixto" repasa el nivel actual y hasta tres por debajo (antes A1–B2 fijo). |

## Data

| File | Purpose |
|------|---------|
| `grammar-data.js` | Loader shim (no rules of its own). Resolves its own script URL via `document.currentScript.src` and `document.write`s the 6 `grammar-data-{level}.js` `<script>` tags in order, so callers keep including a single `grammar-data.js` from any relative/absolute path. Also declares the global `LEVELS` array and initializes `window.GRAMMAR_DATA = {}` before the per-level files populate it. Must stay a plain blocking `<script>` (no `async`/`defer`/`type="module"`) wherever it's included. |
| `grammar-data-a1.js` / `-a2` / `-b1` / `-b2` / `-c1` / `-c2` | Grammar rules for one CEFR level each, populating `window.GRAMMAR_DATA.{LEVEL}` (10 rules/level as of the original split — designed to grow independently per level without bloating a single file). Loaded exclusively via the `grammar-data.js` shim above; never referenced directly by HTML. |
