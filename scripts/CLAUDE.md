# scripts/ (offline tools)

Loaded automatically by Claude Code when files in this directory are read. Split out of the root `CLAUDE.md` (which keeps a one-line index entry per file); keep in sync per the root Maintenance rule.

## Scripts (offline tools)

| File | Purpose |
|------|---------|
| `scripts/seed-word-lists.js` | Node.js script that upserts the Data{LEVEL}.json files (A1→C2) into the `word_lists` Supabase table as system rows (PATCH by `app_id`+`name`, insert if missing; rows not present in the JSON, e.g. `nuevas` from `vocab-refresh.js`, are left untouched). Optional level arg (`node scripts/seed-word-lists.js c1`) seeds only that level — use it after editing one Data file so other levels' rows aren't rewritten. Run after applying `supabase/migrations/001_word_lists_srs.sql`. Requires SUPABASE_URL and SUPABASE_SERVICE_ROLE_KEY in `.env.local`. |
| `scripts/generate-vocab.js` | Generates `Data{LEVEL}.json` files via GPT-4o. Usage: `node scripts/generate-vocab.js [a1\|a2\|b1\|b2\|c1\|c2]`. No arg = all levels. Each category is a separate API call to avoid JSON truncation. Requires OPENAI_API_KEY in `.env.local`. |
| `scripts/generate-reformulaciones.js` | Generates `reformulaciones-data.json` via GPT-4o (one call per grammar rule in `grammar-data.js`, ~20 exercises each). Usage: `node scripts/generate-reformulaciones.js [a1\|…\|c2] [rule-id]`. Flags: `--force` regenerates rules already in the bank, `--dry-run` prints the prompts without calling the API (no key needed). No arg = all levels; existing rules in the file are skipped (incremental); passing a rule-id forces regeneration. Levels present in `reformulaciones-guias.js` (currently C1) use a guided prompt (teacher guide per rule + level complexity requirements, `ejercicios` + 5 spare candidates, sources shorter than `minPalabras` dropped locally) followed by an independent review call like the combos script; the first `ejercicios` that pass review are kept. A failed rule keeps its previous bank entry and doesn't abort the run; the script exits 1 listing failures. Requires OPENAI_API_KEY in `.env.local`. |
| `scripts/generate-reformulaciones-combos.js` | Generates `reformulaciones-combos-data.json` via GPT-4o from the catalog in `reformulaciones-combos.js` (12 exercises per combo). Same pattern/CLI as `generate-reformulaciones.js`: `node scripts/generate-reformulaciones-combos.js [a1\|…\|c2] [combo-id]`; no arg = all levels; incremental (existing combos skipped), passing a combo-id forces regeneration. Validates the catalog first (ids exist, rules at most one CEFR level apart, filed under the highest level, 2-3 rules). Two passes per combo: generation, then an independent review call that drops items that already apply a rule in the source, are ambiguous/invent content, don't need every rule, or have wrong solutions, and appends missing valid solution variants. A failed combo doesn't abort the run; the script exits 1 listing failures. Requires OPENAI_API_KEY in `.env.local`. |
| `scripts/fix-duplicate-words.js` | One-off repair tool for a `generate-vocab.js` generation bug where GPT padded a category to hit its exact requested word count by looping/repeating already-used entries (worst case: 69 of 95 `expresiones` in `DataB2.json` were the same repeated phrase). For each `Data{LEVEL}.json`, detects verbatim duplicates within a category (case-sensitive, article-stripped), removes them, then tries to backfill with genuinely new words via GPT-4o — hard-excluding every word already used at that level or any lower CEFR level (best-effort: if the model keeps re-suggesting already-used words after 3 stalled rounds, it stops and accepts a smaller-than-original category rather than forcing low-quality/misleveled filler). Usage: `node scripts/fix-duplicate-words.js [a1\|…\|c2]`; no arg = all levels. Requires OPENAI_API_KEY in `.env.local`. Not part of the regular build — run manually if a future regeneration reintroduces this bug (now also guarded against directly in `generate-vocab.js`'s `generateCategory`). |
