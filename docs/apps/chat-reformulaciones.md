# chat-reformulaciones.html

Detail doc split out of the root `CLAUDE.md` (which keeps a one-line index entry per file). Keep this file in sync per the root Maintenance rule.

## Active Files row

| File | Purpose |
|------|---------|
| `chat-reformulaciones.html` | Voice/text sentence-transformation (Umformung) practice app. User selects grammar rules from `GRAMMAR_DATA` (in `grammar-data.js`) or random. Tasks come from the pregenerated bank `reformulaciones-data.json` (source sentence without the target structure + instruction in Spanish); zero API cost to generate. Hybrid evaluation: local normalized match against `solutions[]`, with a short `/api/chat` call only when no match (✅/⚠️/❌ by whether the target structure was applied). Falls back to full AI generation (`---NUEVA---` protocol) for rules missing from the bank. Uses `/api/whisper` for voice input, subject to the same shared 60-min/day voice-STT cap. Purple theme (`#6A1B9A`). Rule-level SRS (SM-2 on `rule.id`, IndexedDB `srs-db-reformulaciones` synced to `grammar_rule_progress`) updates on each evaluated turn and powers a "🔁 Repaso SRS" button that starts a session from up to 5 due rules; local session history (IndexedDB `reformulaciones-db`, last 20) is browsable in a collapsible "📚 Historial" panel, no Supabase sync. **Combos mode**: a mode selector (Reglas sueltas / 🔗 Combos, persisted as `cr_mode`; a `?rule=` deep link forces rules mode) switches to curated combos from `reformulaciones-combos.js`, filterable by the same level pills. Combos run only from the pregenerated bank `reformulaciones-combos-data.json` (no AI generation fallback, by design). Random mode ("Aleatorio (3)", or starting with no selection) picks only among curated combos of the filtered level, never arbitrary rule pairs. Evaluation: local normalized match against `solutions[]` counts ✅ for every rule; otherwise a `/api/chat` call (`buildComboEvalPrompt()`) grades each rule separately (`porRegla: [{ruleId, symbol}]`), `resolveComboEval()` derives the overall symbol (all ✅ → ✅, all ❌ → ❌, else ⚠️) and rejects replies that don't grade every rule; `updateRuleSRS()` is called once per rule of the combo (no composite key in `grammar_rule_progress`). The Repaso SRS button is hidden in combo mode. Results screen links each rule of the combo to `gramatica.html`. |

## Data

| File | Purpose |
|------|---------|
| `reformulaciones-data.json` | Bank of reformulation exercises keyed by grammar rule id (~20 per rule): `{ source, instruction, solutions[], explanation }`. Used by `chat-reformulaciones.html`. Generated by `scripts/generate-reformulaciones.js`. |
| `reformulaciones-combos.js` | Curated catalog of multi-rule combos for `chat-reformulaciones.html`'s Combos mode: `window.REFORMULACIONES_COMBOS[LEVEL] = [{ruleIds, titulo, guia?}]` (18 combos A1–B2, keyed by the level of the highest rule; `id` = `ruleIds` joined with `+`, `nivel` derived at load). `guia` pins the exercise shape for the generator (the pilot showed multi-rule combos produce incoherent sentences without it). Loaded via a plain `<script>` in `chat-reformulaciones.html` and by `scripts/generate-reformulaciones-combos.js`. |
| `reformulaciones-combos-data.json` | Bank of combo exercises keyed by combo id (ruleIds joined with `+`): same exercise shape as `reformulaciones-data.json` (`{ source, instruction, solutions[], explanation }`), 18 combos / ~204 exercises. Used by `chat-reformulaciones.html` (Combos mode). Generated by `scripts/generate-reformulaciones-combos.js`. |
