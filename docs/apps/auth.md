# auth.js, config.js, onboarding.js

Detail doc split out of the root `CLAUDE.md` (which keeps a one-line index entry per file). Keep this file in sync per the root Maintenance rule.

## App Scripts

| File | Purpose |
|------|---------|
| `config.js` | Single source of truth para credenciales Supabase (`window.SUPA_URL`, `window.SUPA_KEY`) y VAPID public key (`window.VAPID_PUBLIC_KEY`). Cargado antes de `auth.js` en todas las páginas. Generar VAPID keys con `npx web-push generate-vapid-keys`. |
| `auth.js` | Shared authentication module loaded by all pages. Reads `SUPA_URL`/`SUPA_KEY` globals from `config.js`. Creates `window.sb` (Supabase client), injects the login modal (email+contraseña, OTP y Google OAuth), and exposes `window.openAuthModal`, `window.signInPassword`, `window.savePassword`, `window.logout`, `window.updateAuthUI`, `window.logEvent`, `window.openStatsPanel`, `window.closeStatsPanel`, `window.getAuthToken`, `window.toggleNotifications`, `window.saveNotifSettings`, `window._setNotifInterval`. `openStatsPanel()` renders a right-side drawer with: (1) HOY cards (words answered + audios sent, same font size as the rest); (2) streak; (3) 30-day bar chart; (4) "Actividad últimos 5 días" — per-day pills by app, same weighting as `admin/index.html`'s `renderLast5Days()` (`_APP_NAMES`/`_INFRA_EVENTS` mirrored in `auth.js`, since admin doesn't load it); (5) sección "🔑 Contraseña" (`_renderPassSection()`) — crear o cambiar la contraseña de la cuenta vía `supabase.auth.updateUser({ password })` sobre la sesión ya activa; (6) sección "🔔 Recordatorios" — toggle activar/desactivar push notifications, selector de intervalo (1h/2h/3h/4h/6h) y ventana horaria (desde/hasta). La sección se renderiza via `_renderNotifSection()` que consulta `/api/push-subscribe` para cargar preferencias guardadas. Solo se muestra si `window.VAPID_PUBLIC_KEY` está configurado y el navegador soporta PushManager. **Also owns the shared "Menú ▾" dropdown**: `NAV_ITEMS` is the single source of truth for the 11 nav links + Vocabulario submenu (each entry carries `bodyId` to match `<body id="page-x">` for active-link highlighting); `_renderNavMenu()` builds the `.nav-dropdown-menu` DOM from it on `DOMContentLoaded`, before `updateAuthUI()` appends the admin-only `ADMIN_LINKS` via `_addDashboardLink()`. The 17 pages that use this nav only ship an empty `<div class="nav-dropdown-menu"></div>` — add/reorder/rename menu items only in `NAV_ITEMS`, never per-file. The 7 PWA service workers (`sw.js`, `sw-a1.js`, `sw-a2.js`, `sw-b1.js`, `sw-c1.js`, `sw-c2.js`, `sw-plan.js`) precache `auth.js`, `config.js`, and the Supabase CDN script so the JS-rendered menu still works offline. **Daily active-time tracking** (local-first, per app): a heartbeat (`_dtTick()`, every 15s while `document.visibilityState === 'visible'` and a user is signed in) accumulates ms per app into a `localStorage` key scoped to that calendar day (`ejaleman_daily_time_<YYYY-MM-DD>`, `{appId: ms}`) — zero DB calls during the day, and a day rolling over mid-session just starts writing to a new key without touching the previous day's. The app id per page comes from `document.body.id` via the `_DT_BODY_APP` map (falls back to a path-based slug for admin/teacher/marketing/chatvoz2, which have no body id); `chatvoz2/index.html`'s body id was renamed `page-cv2` (was colliding with `chat-voz.html`'s `page-cv`, which would have merged their tracked time — `styles.css`'s `#page-cv` theme rules were extended to also match `#page-cv2` so the visual theme is unaffected). On sign-in/page-load/tab-refocus, `_dtSyncStaleDays()` scans for any `ejaleman_daily_time_*` key that isn't today's, sends **one** `supabase.rpc('upsert_daily_usage_time', {p_date, p_apps})` call per stale day found, and removes the key on success — so syncing only happens on day transitions, not per session. The RPC (migration `016_daily_usage_time.sql`) is `security definer`, additively merges `apps` per key (so multiple devices syncing the same day sum instead of overwrite) and prunes rows older than 60 days for that user on every call. If the user never reopens the app, that last day's local record is lost — an accepted tradeoff (no `sendBeacon` fallback). **Feedback button** (`_injectFeedbackButton()`/`_injectFeedbackModal()`): a global fixed "💬" FAB (`#feedback-fab`, bottom-right, injected on every page on `DOMContentLoaded`) opens a modal (tipo bug/sugerencia + mensaje) — `window.submitFeedback()` inserts into `feedback_reports` (`{user_id, tipo, mensaje, pagina: location.pathname}`) via `window.sb`, then fires a fire-and-forget `POST /api/push-subscribe` with `{action: 'notify-admins', report_id}` to alert admins who have push notifications enabled. Prompts login (`window.openAuthModal()`) instead of opening the modal if no user is signed in. **Login por contraseña**: el modal ofrece email+contraseña como camino principal (`window.signInPassword()` → `signInWithPassword`), con el OTP degradado a enlace secundario ("Entrar con un código al correo"). No hay `signUp` ni flujo de reset por email a propósito: toda cuenta nace por OTP o Google (verificando el email de paso) y la contraseña se crea después desde el panel "Mi progreso"; quien la olvide entra con un código y la reescribe ahí, así que no hacen falta `resetPasswordForEmail`, una página `/reset-password` ni Redirect URLs extra en Supabase. Los errores del modal se muestran inline en `#auth-error` (`_authError()`), ya no con `alert()`. **Active session / device tracking** (concurrency detection): a stable device id (`crypto.randomUUID()`, persisted in `localStorage` as `ejaleman_device_id`, one per browser regardless of which account logs in) is upserted into `active_sessions` every 60s while the tab is visible and a user is signed in (`_asTick()`/`_asInit()`), plus once immediately on sign-in/page-load/tab-refocus (`_asForceTick()`, mirrors `_dtSyncStaleDays()`'s call sites). The device label sent (`_asDeviceLabel()`) is a short browser+OS guess parsed from `navigator.userAgent` (e.g. "Chrome · Windows"), not the raw UA string. Writes go through the `upsert_active_session(p_session_id, p_device)` RPC (migration `018_active_sessions.sql`), which also prunes that user's own devices inactive for 7+ days. Read by `admin/index.html`'s user detail panel to list devices and flag simultaneous use. |
| `onboarding.js` | Guided tour for first-time visitors, loaded by `index.html`. Spotlight overlay with 6 steps: welcome + CEFR level picker (persisted as `onboarding_level`), vocab card of the chosen level, plan 30 días, Menú dropdown, auth button, final CTA ("Ir a mi nivel"). Runs once (`onboarding_done_v1` in localStorage); relaunchable via fixed "?" button (bottom-left) or `window.startOnboarding()`. |
