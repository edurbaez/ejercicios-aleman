## lectura veloz.html — Implementation Notes

### Core concept
RSVP (Rapid Serial Visual Presentation): splits a text into chunks and flashes them one at a time in a large centered display at a configurable WPM. The pedagogical frame is that raw speed is meaningless without comprehension, so the activity is built around **effective reading rate** (real WPM × % comprehension), measured per pass and kept in IndexedDB.

### WPM control
`+`/`−` buttons adjust WPM in steps of 10. The starting value comes from the student's `onboarding_level` via `LV_WPM_POR_NIVEL` (A1 120 → C2 300) — a flat 400 is native-L1 speed and unreadable for a beginner in German. Per-chunk delay is `chunkDelay()`: `60000/wpm × chunk length`, scaled by average word length (0.8–2.2×, so Komposita get their time) and then by the punctuation pause (×2 after `.!?…`, ×1.5 after `,;:`).

### Chunking modes (`cycleChunkMode()`, persisted as `lv_chunk_mode`)
- `one` — one word at a time.
- `two` — two words, paired by position.
- `sinn` — **Sinneinheiten**: up to `LV_CHUNK_MAX` (5) words grouped by syntax. `chunkSizeAt()` opens a group at any preposition or conjunction in `LV_INICIO_GRUPO` and cuts on trailing punctuation; articles never cut, so determiners stay with their noun. This exists because German holds the separable prefix and the subordinate-clause verb until the end — pairing words two by two breaks exactly the parsing skill the exercise should train.

### Word display
- ORP (Optimal Recognition Point) — the focal letter of the first word is highlighted in red inside `#display`.
- Font size shrinks as the chunk grows (48px → 26px) so long compounds don't overflow the box.
- Progress bar and `Palabra N de Total` counter update on each chunk.
- Start position input lets the user jump to a specific word index before playing.

### End of pass, comprehension and history
- `lvFinalizarLectura()` closes the pass: real WPM is computed from words actually read (`lvSesion.desde` onwards) and the accumulated active time (`lvAcumularTiempo()` excludes pauses), then the pass is written to the IndexedDB `sesiones` store.
- `#lv-finish` offers **📖 Comprobar comprensión** — `lvComprobarComprension()` loads the text into Comprensión Modo A and sets `lvPendiente`; when `compMostrarResultado()` runs, `lvAplicarComprension()` writes `comprensionPct`/`wpmEfectivo` back to the stored pass and renders the effective rate in `#lv-efectivo`. `lvPendiente` is cleared by `compSwitchMode()`/`compReintentar()` so a later standalone Modo A run doesn't pick up a stale reading.
- **🔁 Releer** (`lvLeerOtraVez()`) repeats the same text at +10% WPM — repeated reading, with the history showing whether comprehension held.
- `#lv-historial` (`lvRenderHistorial()`) shows total readings, mean and best effective WPM, and the last 10 passes. Local only: no Supabase table, and `dbSesionesPodar()` keeps at most 100 rows.

### Lexical coverage (`lvAnalizarTexto()`)
Below ~95% known words fluent reading stops working, so the reader can check a text before committing to it. The known-word set (`lvPalabrasConocidas()`, cached per session, invalidated on sign-in) is `LV_FUNCIONALES` + the vocabulary of the student's level and every level below (`sprintLevelPairs`) + their `srs_progress` rows with `reps >= 2`. Verdict thresholds: ≥95% green, 90–94% orange, <90% red. The most frequent unrecognised words are rendered as chips that translate on tap.

`lvEsConocida()` is a heuristic, **not** a lemmatizer: `lvIndexarEntrada()` stores each entry plus an approximate root, `lvCoincide()` trims up to 3 trailing characters, and participles are handled both as `ge-…-t/-en` and as separable verbs (`angerufen` → `rufen`, via `LV_PARTICIPIO_SEPARABLE`). Strong irregulars (`ging` ← `gehen`) still read as unknown; the panel says the figure is an estimate.

### Levelled texts from the system (`lvTraerTextoSistema()`)
`#lv-source` pulls a text of the chosen level from `reading_texts`, preferring rows the user hasn't got in `user_reading_seen`. `lvTextoPlano()` flattens the row: `format_version` 1 uses `content`; 2 concatenates `questions.teile[].textos` (prose only — the exam tasks stay in Comprensión). Requires a signed-in user.

### Text input
- Paste text directly into the `<textarea>`.
- File upload: supports `.txt`, `.pdf` (via pdf.js), `.doc`/`.docx` (via mammoth.js).
- Parsed text is loaded into the word array without saving unless the user explicitly saves.

### Saved texts (IndexedDB `lecturaVeloz`, store `textos`)
- Each record is `{ id, name, text, level, words }`; `level` and `words` are set in `showSaveTextDialog()` and shown as badges in the list. `migrateFromLocalStorage()` still imports the legacy `textosguardados` key, and `mostrarTextosGuardados()` falls back to `contarPalabras()` for records saved before this field existed.
- Each saved item shows name, level, word count, preview, and Load / leer / rename / Delete buttons.
- Last reading position is stored per item as `lv_pos_<id>` in localStorage so reading resumes where left off.
- `syncToCloud()` mirrors name, text, level and words into `user_data.lv_texts` (jsonb — no migration needed for the added fields).

### Blog view
A secondary reading mode: the saved text is displayed as a full paragraph with 150-character chunks. Chunks are highlighted as TTS reads through them. Double-clicking a chunk sets the start position. A language selector (`#blog-lang`, **`de-DE` by default**) picks the TTS language and a rate slider (`#blog-rate`, persisted as `lv_blog_rate`, default 0.85×) slows the voice down — below 1× the audio accompanies the reading instead of outrunning it. Every word is wrapped by `lvChunkConPalabras()` and tapping one shows its translation in `#lv-tooltip` (`lvTraduccion()`: `diccionario_cache` first, `/api/chat` only on a miss, then written back to the cache). A thin progress bar (`#blog-progress-bar`) below the controls shows `currentChunk / totalChunks` as a percentage; updated in `highlightChunk(i)` and reset to 0 in `salirBlogView()`.

### Panel visibility
`lvMostrarPaneles(visible)` is the single place that shows/hides the Lectura veloz panels, used by both `switchActivity()` and `entrarBlogView()`/`salirBlogView()`. `LECTURA_IDS` are restored unconditionally; `LECTURA_IDS_COND` (`lv-analisis`, `lv-finish`) only reappear when they still hold content (`dataset.active === '1'`).

### Navbar
All pages share a fixed navbar. **Inicio** (`B2.html`) is always visible as a standalone link. The remaining pages (Lectura Veloz, Diccionario, B1, Chat de Voz) are grouped under a **Menú ▾** dropdown button. Dropdown toggled via `classList.toggle('open')` on click; closes on outside click via a `document` listener in each HTML file. Styles in `styles.css` under the shared navbar section.

### Dark mode
Toggled by a fixed button; persisted via `window.ThemePref` (shared `ejaleman_theme` key, see `auth.js`).

### External libraries (CDN)
- `pdf.js 3.11.174` — PDF parsing.
- `mammoth 1.6.0` — `.docx` parsing.
